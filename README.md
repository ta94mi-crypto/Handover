# ניהול מסירות אתר בנייה

תוכנה פשוטה למעקב מסירות בשטח: מעלים תוכנית לכל קומה, מסמנים חדרים על גבי התוכנית,
ורושמים לכל חדר הערות/ליקויים עם תמונה, מקצוע (מיזוג / חשמל / אינסטלציה וכו') וקבלן/תת-מקצוע
(לדוגמה בתוך מיזוג: פחח, צנרן, מבודד). יש טבלה מרכזית עם סינון (לפי קומה, חדר, מקצוע, קבלן,
סטטוס) לצורך שליחת רשימת המשימות של כל קבלן, וייצוא ל-CSV. כשמתקנים אפשר לסמן "טופל" עם או
בלי תמונת תיקון.

כל מי שנכנס לכתובת של השרת רואה את אותם הנתונים בזמן אמת (מסד נתונים משותף אחד) —
זה מה שהופך אותו ל"אתר שכולם רואים בלייב".

## הרצה מקומית

דרישה: Node.js גרסה 22.5 ומעלה (נעשה שימוש במודול `node:sqlite` המובנה, כך שאין צורך
בהתקנת מסד נתונים נפרד או קומפילציה של מודולים native).

```bash
npm install
npm start
```

השרת יעלה בכתובת `http://localhost:3000`. אפשר לשנות פורט עם משתנה סביבה `PORT`.

לפיתוח עם ריענון אוטומטי בשינוי קבצים:

```bash
npm run dev
```

## מבנה הנתונים

מבנה (בניין/אתר) → קומות (עם תמונת תוכנית) → חדרים (מסומנים על התוכנית או ברשימה) →
רשומות (הערה/ליקוי) שכל אחת מהן שייכת למקצוע ולקבלן/תת-מקצוע, כוללת תמונות, וסטטוס
"פתוח"/"טופל".

מקצועות וקבלנים ברירת מחדל נטענים אוטומטית בהרצה הראשונה (מיזוג אוויר, חשמל, אינסטלציה,
גבס ותקרות, ריצוף וחיפוי, אלומיניום וזכוכית, נגרות, מעליות, כללי) וניתן לערוך אותם
במסך "מקצועות וקבלנים" — אפשר גם להוסיף מקצוע/קבלן חדש ישירות מתוך טופס הוספת הערה.

הנתונים נשמרים בקובץ SQLite מקומי ב-`data/handover.db`, והתמונות נשמרות בתיקיית
`uploads/`. שתי התיקיות לא נכללות ב-git (ראו `.gitignore`) — הן נוצרות אוטומטית בהרצה
הראשונה של השרת. אפשר להעביר את שתי התיקיות למיקום אחר (למשל דיסק קבוע בענן) עם משתנה
הסביבה `STORAGE_DIR` — ראו בהמשך.

## פרסום כאתר חי לכל הצוות (Render)

כדי שכולם (קבלנים, מנהל עבודה וכו') ייכנסו מהטלפון ויראו עדכון בזמן אמת, צריך להריץ את
השרת על שירות שנגיש מהאינטרנט. ההוראות כאן ל-[Render](https://render.com) כי הוא
מתחבר ישירות ל-GitHub ופשוט להקמה:

1. נכנסים ל-render.com ומתחברים עם חשבון ה-GitHub הקיים.
2. **New +** → **Web Service** → בוחרים את הריפו `Handover`, וענף
   `claude/construction-handover-management-hvkax2` (או `main` אחרי מיזוג).
3. הגדרות בנייה:
   - **Runtime**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
4. **חשוב — דיסק קבוע**: בלי זה, כל הנתונים (חדרים, ליקויים, תמונות) יימחקו בכל פריסה
   מחדש או הפעלה מחדש של השירות, כי Render מוחק את מערכת הקבצים בין הרצות. בתוכנית
   החינמית אין דיסק קבוע, אז צריך תוכנית בתשלום (Starter, כ-7$ לחודש) ולהוסיף שם
   **Disk**:
   - Mount Path: `/var/data`
   - גודל: 1GB מספיק להתחלה, אפשר להגדיל בהמשך.
   - ואז מגדירים משתנה סביבה (Environment) בשירות: `STORAGE_DIR` = `/var/data`
     (כך גם מסד הנתונים וגם התמונות נשמרים על אותו דיסק קבוע).
5. שומרים ומפרסמים (Deploy). Render ייתן כתובת קבועה כמו
   `https://handover-xxxx.onrender.com` — זה הקישור לשלוח לצוות ולקבלנים.

**VPS פרטי** (חלופה, דורשת יותר ידע טכני): מכונה עם Node מותקן, מריצים עם `pm2` או
כ-systemd service כדי שהשרת ימשיך לרוץ ברקע, ומציבים Nginx כ-reverse proxy עם HTTPS
(Let's Encrypt) מול דומיין. גם כאן `STORAGE_DIR` יכול להצביע לתיקייה קבועה בדיסק.

## שימוש

1. **מבנים** — יוצרים מבנה/אתר חדש (למסך הבית).
2. בתוך המבנה — יוצרים **קומה**, ומעלים אליה תמונת תוכנית (סריקה/צילום של תוכנית הקומה).
3. לוחצים על התוכנית במיקום הרצוי כדי **להוסיף חדר** מסומן על המפה, או "+ הוסף חדר" לחדר
   ללא סימון מדויק.
4. לוחצים על חדר (על המפה או ברשימה) כדי לפתוח אותו ולהוסיף **הערה/ליקוי**: בוחרים מקצוע
   (או מוסיפים חדש), קבלן/תת-מקצוע בתוך אותו מקצוע (או מוסיפים חדש), כותבים הערה ומצלמים
   תמונה.
5. במסך **טבלת ליקויים** — מסננים לפי קומה/חדר/מקצוע/קבלן/סטטוס/חיפוש חופשי, ומייצאים
   CSV או מדפיסים כדי לשלוח לקבלן ספציפי את כל המשימות שלו.
6. כשקבלן מתקן ליקוי — פותחים את הרשומה ולוחצים "**סמן כטופל**", עם אפשרות לצרף תמונת
   תיקון (לא חובה).

## הרחבות אפשריות בהמשך

- התחברות עם משתמש/סיסמה או קישור ייחודי לכל קבלן שמראה רק את הפריטים שלו.
- שליחת הרשימה המסוננת ישירות בוואטסאפ/מייל לקבלן.
- ריבוי משתמשים עם היסטוריית שינויים (מי סימן כטופל ומתי).
